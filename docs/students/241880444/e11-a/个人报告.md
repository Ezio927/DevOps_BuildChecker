## 4. 本人的实现改动与八项测试

课程原实现仅比较目标 findings。本次新增 verify_incremental：
先检查增量 payload 的 commit，再核对对象 actual 图、declared 图，最后比较精确发现集合。
避免“错误集合相同，但图已经损坏”仍被判定成功。

新增八项 A 契约测试全部通过：
1. 正确图与精确发现通过；
2. findings 相同但 actual 图缺边，返回 GRAPH_MISMATCH；
3. findings 相同但 declared 图错误，返回 DECLARATION_MISMATCH；
4. payload 属于旧提交，返回 STALE_REPORT；
5. 外层 envelope 属于旧提交，返回 STALE_REPORT；
6. 错误产物类型被拒；
7. 错误 schema 被拒；
8. 文件内容变化导致 ARTIFACT_HASH_MISMATCH。

对真实 standard/incremental-check.json 的副本改为旧 commit，check_envelope 明确拒绝，
expected-stale-rejection.json 记录 STALE_REPORT，原始报告字节未改变。
运行器 --a-only 对非 A 请求直接拒绝，不启动 API；构建复用 A 工具链，不下载 B 构建专用 Docker CLI 镜像。
